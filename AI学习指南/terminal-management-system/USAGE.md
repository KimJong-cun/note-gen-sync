# 智能终端管理系统 - 使用指南

**版权所有: KimJong**

## 快速开始

### 1. 启动系统

```bash
cd terminal-management-system
npm start
```

启动成功后,您将看到:

```
========================================
  智能终端管理系统
  版权所有: KimJong
========================================

服务器启动完成!
前端地址: http://127.0.0.1:3000
WebSocket地址: ws://127.0.0.1:8080
```

### 2. 访问前端界面

打开浏览器访问: **http://127.0.0.1:3000**

⚠️ **重要**: 必须通过HTTP服务器访问,不能直接打开HTML文件!

### 3. 连接到WebSocket服务器

在前端界面中:

1. **服务器地址**: 保持默认 `127.0.0.1`
2. **端口**: 保持默认 `8080`
3. 点击 **"连接"** 按钮

连接成功后,状态指示灯会变成绿色,显示"已连接"。

### 4. 发送消息

1. 在"消息发送"区域的文本框中输入消息
2. 点击 **"发送消息"** 按钮,或按 `Ctrl + Enter`
3. 消息将被发送到服务器并转发给所有连接的客户端

### 5. 测试消息转发功能

要完整测试转发功能,需要打开多个浏览器窗口:

1. 在第一个窗口连接到WebSocket服务器
2. 打开第二个浏览器窗口,访问 http://127.0.0.1:3000
3. 在第二个窗口也连接到服务器
4. 在任一窗口发送消息
5. 所有窗口都会收到该消息

## 界面说明

### WebSocket连接配置

- **服务器地址**: WebSocket服务器的IP地址
- **端口**: WebSocket服务器的端口号
- **连接按钮**: 建立WebSocket连接
- **断开按钮**: 断开当前连接
- **状态指示器**: 显示当前连接状态

### 消息发送区

- **消息输入框**: 输入要发送的消息内容
- **发送消息按钮**: 发送消息到服务器
- 快捷键: `Ctrl + Enter` 发送消息

### 消息日志

- 实时显示所有消息和系统事件
- 不同类型消息用不同颜色标识:
  - 🔵 蓝色 - 系统消息
  - 🟢 绿色 - 发送的消息
  - 🟠 橙色 - 接收的消息
  - 🔴 红色 - 错误消息
- **清空日志按钮**: 清除所有日志记录

### 连接信息

- **当前连接**: 显示当前连接的WebSocket地址
- **消息统计**: 显示发送和接收的消息数量

## 消息类型

### 系统消息

服务器在以下情况发送系统消息:

- 客户端连接成功时
- 服务器发生错误时

示例:
```json
{
  "type": "system",
  "message": "欢迎连接到智能终端管理系统",
  "timestamp": "2025-11-06T12:00:00.000Z"
}
```

### 转发消息

服务器将客户端发送的消息转发给所有连接的客户端:

```json
{
  "type": "forward",
  "data": {
    "data": "原始消息内容",
    "isSelf": true
  },
  "timestamp": "2025-11-06T12:00:00.000Z"
}
```

- `isSelf`: 标识是否是自己发送的消息

### 错误消息

当发生错误时,服务器发送错误消息:

```json
{
  "type": "error",
  "message": "错误描述",
  "timestamp": "2025-11-06T12:00:00.000Z"
}
```

## 高级功能

### 自定义服务器地址

如果WebSocket服务器运行在其他机器上:

1. 修改"服务器地址"为目标IP地址
2. 修改"端口"为目标端口
3. 点击"连接"

示例:
- 服务器地址: `192.168.1.100`
- 端口: `8080`

### 自动重连

如果连接意外断开,系统会自动尝试重连:

- 最多尝试 **5次**
- 每次间隔 **3秒**
- 可以在日志中看到重连尝试

### 自定义端口启动

启动时可以自定义端口:

**Windows:**
```bash
set HTTP_PORT=8888 && set WS_PORT=9999 && npm start
```

**Linux/Mac:**
```bash
HTTP_PORT=8888 WS_PORT=9999 npm start
```

### 仅启动WebSocket服务器

如果只需要WebSocket服务器(使用自己的前端):

```bash
npm run ws-only
```

### 仅启动HTTP服务器

如果WebSocket服务器在其他地方运行:

```bash
npm run http-only
```

## 故障排除

### 问题: 无法连接到WebSocket服务器

**解决方案:**

1. 检查服务器是否已启动
2. 检查服务器地址和端口是否正确
3. 检查防火墙设置
4. 查看浏览器控制台是否有错误信息

### 问题: 前端页面无法访问

**解决方案:**

1. 确保HTTP服务器已启动
2. 确保访问的是 http://127.0.0.1:3000 而不是直接打开HTML文件
3. 检查端口3000是否被其他程序占用

### 问题: 消息没有转发

**解决方案:**

1. 确保至少有2个客户端连接
2. 检查服务器控制台是否有错误
3. 查看消息日志区域是否有错误提示

### 问题: 页面样式显示不正常

**解决方案:**

1. 清除浏览器缓存
2. 强制刷新页面 (Ctrl + F5)
3. 检查CSS文件是否正确加载

## 开发建议

### 查看调试信息

打开浏览器开发者工具 (F12):

- **Console**: 查看JavaScript日志
- **Network**: 查看WebSocket连接状态
- **Network > WS**: 查看WebSocket消息

### 测试场景

**场景1: 单客户端测试**
- 连接服务器
- 发送消息
- 检查是否收到自己的消息

**场景2: 多客户端测试**
- 打开2-3个浏览器窗口
- 都连接到同一个服务器
- 在任意窗口发送消息
- 检查所有窗口是否都收到

**场景3: 断线重连测试**
- 连接服务器
- 停止WebSocket服务器
- 观察自动重连行为
- 重新启动服务器
- 检查是否自动连接成功

**场景4: 错误处理测试**
- 输入错误的服务器地址
- 尝试连接
- 检查错误提示

## 性能优化建议

1. **消息日志**: 定期清空日志,避免DOM元素过多
2. **长连接**: WebSocket连接会一直保持,注意资源管理
3. **大数据**: 发送大量数据时,考虑分片传输

## 安全注意事项

⚠️ **当前版本为开发版本,生产环境使用前请注意:**

1. 使用 `wss://` (WebSocket Secure) 而不是 `ws://`
2. 添加身份验证机制
3. 添加消息加密
4. 实施速率限制
5. 添加消息内容验证

## 扩展开发

### 添加新的消息类型

1. 在 `backend/websocket-server.js` 中处理新消息类型
2. 在 `frontend/js/app.js` 的 `handleReceivedMessage()` 方法中添加处理逻辑

### 添加新的UI功能

1. 在 `frontend/index.html` 中添加HTML结构
2. 在 `frontend/css/style.css` 中添加样式
3. 在 `frontend/js/ui-controller.js` 中添加UI逻辑
4. 在 `frontend/js/app.js` 中关联业务逻辑
